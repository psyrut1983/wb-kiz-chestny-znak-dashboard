# WB КИЗы для Честного знака

Проект состоит из двух частей:

- `Code.gs` — загрузка и сортировка КИЗов внутри Google Таблицы через Apps Script.
- `index.html` — отдельная HTML-панель для GitHub Pages, которая напрямую работает с Google Таблицей через Google Sheets API и формирует файлы для Честного знака.

## Таблица

https://docs.google.com/spreadsheets/d/1Ol0SdvkxilSx5wnjwiUqWjDL6lpzWU8bGR5-xERWCe8/edit

## Запуск табличной части

1. Открыть таблицу.
2. `Расширения` -> `Apps Script`.
3. Вставить `Code.gs`.
4. Сохранить.
5. Обновить таблицу.
6. Меню `WB КИЗы` -> `1. Подготовить таблицу`.
7. На листе `Настройки` заполнить два юрлица: название, ИНН, WB API токен и константы для Честного знака.
   - Для текущих FBS-заказов оставить `Режим WB API = fbs`.
   - Для выгрузки вывода из оборота заполнить `ФИАС / МОД`.
   - Токен WB должен иметь доступ к категориям `Аналитика` и `Статистика`, иначе чек/цена из отчёта маркировки и запасная диагностика WB не отработают.
8. Если нужно заменить токен: `WB КИЗы` -> `3. Обновить WB API токен`.
   - Кнопка проверяет новый токен по Marketplace, Analytics и Statistics.
   - Если проверка не прошла, старый токен не перезаписывается.
9. Меню `WB КИЗы` -> `2. Загрузить данные за вчера`.
10. Если нужно догрузить цену и чек по уже существующим строкам: `WB КИЗы` -> `4. Догрузить чеки и цены WB`.
11. Если отчёт маркировки WB возвращает 0 строк: `WB КИЗы` -> `5. Диагностика WB Статистика`.
    - Диагностика сначала читает `supplier/orders` и пробует заполнить пустой `SRID` в листе к выводу по однозначному совпадению `артикул + баркод + дата/время заказа`.

## Логика

- `Настройки` хранит настройки двух юрлиц.
- Для каждого юрлица создаются три листа:
  - `Юрлицо 1 - КИЗы к выводу` / `Юрлицо 2 - КИЗы к выводу`;
  - `Юрлицо 1 - КИЗы к вводу` / `Юрлицо 2 - КИЗы к вводу`;
  - `Юрлицо 1 - Архив выведенных КИЗов` / `Юрлицо 2 - Архив выведенных КИЗов`.
- `Журнал синхронизации` хранит историю запусков.
- `Ошибки` хранит ошибки WB/API/обработки.
- Дубли отсекаются по служебному ключу внутри строки: юрлицо + операция + КИЗ + заказ WB.
- Для FBS скрипт получает статусы через `POST /api/v3/orders/status`.
- КИЗы берутся из metadata через `POST /api/marketplace/v3/orders/meta`.
- Цена, номер чека, дата чека и короткий КИ для Честного знака подтягиваются из отчёта WB по обязательной маркировке: `POST https://seller-analytics-api.wildberries.ru/api/v1/analytics/excise-report`.
- Отчёт WB по маркировке склеивается со строками по `SRID`, а если `SRID` не совпал — по коду маркировки.
- Запасная диагностика WB Статистика проверяет `GET https://statistics-api.wildberries.ru/api/v1/supplier/orders`: она показывает, есть ли в отчёте строки и SRID для склейки, и заполняет `SRID` в листе к выводу только при однозначном совпадении по артикулу, баркоду и времени заказа. `supplier/sales` нужно запускать отдельным следующим шагом после SRID, чтобы не упираться в лимит WB Статистика; номер чека эти методы не отдают.
- Статус WB `canceled_by_client` попадает во ввод обратно в оборот.
- КИЗ к вводу обратно добавляется только если он уже есть в архиве.
- Отмены продавца, отмены в первый час и брак пропускаются.
- Остальные заказы с найденным `sgtin` попадают в вывод из оборота, если этот КИЗ ещё не лежит в архиве.

## Публичная HTML-панель через Apps Script

Это максимально простой режим под задачу "открыл ссылку и пользуешься": панель публикуется как Apps Script Web App и выполняется от имени владельца скрипта. Отдельный вход в Google для каждого пользователя не нужен.

Риски осознанные: любой человек с web app ссылкой сможет читать строки панели, скачивать файлы для Честного знака и подтверждать операции, которые меняют листы таблицы.

Запуск:

1. В Apps Script добавить HTML-файл с именем `Public`.
2. Вставить туда содержимое `Public.html` из этого репозитория.
3. В `Code.gs` должны быть функции `doGet`, `getPublicDashboardData`, `confirmPublicWithdraw`, `confirmPublicIntroduce`.
4. `Deploy` -> `New deployment` -> тип `Web app`.
5. `Execute as`: `Me`.
6. `Who has access`: `Anyone`.
7. Скопировать web app URL и отправлять его тем, кому нужен доступ.

## GitHub Pages HTML-панель с OAuth

HTML-панель не открывается внутри Google Таблицы. Её нужно публиковать как статическую страницу GitHub Pages.

Минимальная схема:

1. Включить Google Sheets API в Google Cloud.
2. Создать OAuth Client ID для Web application.
3. Добавить GitHub Pages URL в разрешённые JavaScript origins.
4. Открыть `index.html` через GitHub Pages.
5. Вставить OAuth Client ID в поле подключения.
6. Нажать `Войти Google`.
7. Разрешить доступ к Google Таблицам.

Панель хранит `spreadsheetId` и OAuth Client ID только в `localStorage` браузера. Постоянные секретные токены в HTML не зашиваются.

## HTML-логика

Панель умеет:

- читать лист `Настройки`;
- по названиям из `Настройки` читать листы конкретных юрлиц;
- показывать КИЗы к выводу, к вводу обратно и архив;
- выбирать строки;
- формировать файлы для Честного знака;
- после ручного подтверждения переносить строки через Google Sheets API.

CSV для вывода из оборота:

- формат соответствует шаблону Честного знака с двумя блоками: реквизиты документа и `Параметры товаров`;
- `ИНН участника оборота` берётся из `Настройки`;
- `Причина вывода из оборота` берётся из `Настройки`, по умолчанию `Дистанционная продажа`;
- `Другая причина вывода из оборота` заполняется только если причина `Другое`;
- `Тип первичного документа` берётся из `Настройки`, по умолчанию `Кассовый чек`;
- `Идентификатор ФИАС` берётся из `Настройки`;
- в строках товаров заполняются `КИ`, `Цена за единицу`, `Тип первичного документа`, `Номер первичного документа`, `Дата первичного документа`;
- `Номер первичного документа` и `Дата первичного документа` в строках товаров берутся из полей `Номер чека` и `Дата чека`;
- CSV не скачивается, если у выбранных строк нет КИ, цены, номера чека, даты чека, ИНН или ФИАС;
- файл формируется без BOM, с LF-переносами строк и без завершающего перевода строки;
- версия CSV-шаблона берётся из `Настройки`, по умолчанию `7`.

XML для ввода обратно в оборот:

- корневой тег `return`, версия `1`;
- ИНН из `Настройки`;
- `return_type = REMOTE_SALE_RETURN` — возврат при дистанционном способе продажи;
- `primary_document_number` формируется автоматически в формате `WB-FBS-RETURN-ИНН-ДАТА-ВРЕМЯ`;
- КИЗы идут в `products_list/product/ki`.

Подтверждение движения строк остаётся двухфазным:

1. Сначала сформировать и скачать файл.
2. Вручную загрузить файл в Честный знак.
3. Только после этого нажать подтверждение в HTML-панели.

## Старые серверные функции

HTML-панель должна вызывать серверные функции Apps Script:

- `confirmWithdrawDone(entityId)` — после ручного вывода в Честном знаке переносит строки из листа `КИЗы к выводу` в лист `Архив выведенных КИЗов`.
- `confirmIntroduceDone(entityId)` — после ручного ввода обратно очищает лист `КИЗы к вводу` и удаляет эти КИЗы из листа `Архив выведенных КИЗов`.

Новая внешняя HTML-панель эти функции не использует: она работает напрямую с Google Sheets API. Функции оставлены в `Code.gs` как резерв для табличной части.
